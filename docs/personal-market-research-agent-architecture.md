# 개인용 시장 리서치 하네스의 에이전트 아키텍처

> 이 문서는 사용자가 제공한 증권업계 시장 구조 리서치를 제품 요구사항으로 해석한
> 아키텍처 제안이다. 법률 의견이 아니며, 보고서에 포함된 법령·라이선스 판단을 독립적으로
> 검증하지 않는다.

## 결론

현재 코스피 하네스처럼 매 질문마다 18명의 고정 전문가를 호출하는 구조를 범용 개인
리서치 터미널의 기본값으로 사용하지 않는다. 목표 구조는 다음과 같다.

1. **수집·계산·검증·정책 집행은 코드가 담당한다.**
2. **AI는 질문 계획, 문서 의미 해석, 가설, 반론, 설명에만 사용한다.**
3. **전문가는 상시 조직이 아니라 필요할 때 선택되는 풀이다.**
4. **공시·실적·스크리닝·포트폴리오·매크로를 서로 다른 워크플로우로 운영한다.**
5. **주문 실행과 외부 배포 경로는 아키텍처에 넣지 않는다.**

코스피 저점 하네스는 가장 무거운 `deep_research` 워크플로우로 유지하되, 일상적인
조회·모니터링·요약의 기본 엔진으로 재사용하지 않는다.

## 변경 전후

```text
현재
질문 → 고정 도메인 전문가 다수 → 시나리오 3명 → 검증 3명 → IC → 보고서

제안
질문 → 코드 정책 게이트 → 작업 라우터 → 필요한 수집기/계산기
     → Evidence Pack → 필요한 분석가 0~3명 → 선택적 반론 → 리서치 편집자
```

현재 구조는 한 개의 복잡한 투자 테제를 깊게 검토하는 데 적합하다. 범용 시스템에서는
단순 공시 알림에도 거시·지정학·행동재무·세 가지 시나리오를 모두 호출하게 되어 지연,
토큰 비용, 중복 검색, 책임 경계가 커진다.

## 세 계층으로 분리한다

### 1. 결정적 제어 계층 — 에이전트가 아님

다음 역할은 Python 코드와 스키마로 구현한다.

| 모듈 | 책임 |
|---|---|
| `policy_gate` | 자기사용 여부, 주문 금지, 외부 배포 금지, 데이터 사용범위 검사 |
| `source_catalog` | DART·EDGAR·ECOS·FRED·증권사 API별 인증·요율·출처·라이선스 메타데이터 |
| `collector_runtime` | 고정 어댑터 또는 에이전트 생성 수집기 실행, 원문·로그·해시 보존 |
| `normalizer` | 기업 식별자, 날짜, 통화, 단위, 회계기간, 지표 정의 통일 |
| `calculator` | 변화율, 멀티플, 컨센서스 차이, VaR, 익스포저, 이벤트 서프라이즈 계산 |
| `validator` | 숫자·날짜·중복·원자료 계열·산식·인용 일치 검사 |
| `renderer` | 표·차트·출처·고지문을 템플릿으로 생성 |

특히 라이선스와 규제 경계는 AI의 주의 문구에만 의존하지 않는다. 각 소스와 산출물에
다음과 같은 기계 판독 필드를 붙이고, 정책 위반 시 실행을 차단한다.

```json
{
  "use_scope": "self_only",
  "redistribution": "prohibited",
  "attribution_required": true,
  "contains_account_data": false,
  "execution_allowed": false,
  "output_class": "research_draft"
}
```

`collector_runtime`은 이전 PR의 `generated_csv`/`generated_json`을 사용한다. 에이전트가
API 또는 브라우저 수집 코드를 쓸 수 있지만, 원문 보존·실행 제한·환경변수 전달·해시와
검증은 런타임이 담당한다.

### 2. 소수의 상시 에이전트

범용 시스템에서 항상 사용할 에이전트는 세 종류면 충분하다.

> **구현 상태 (2026-08-04)**: `.claude/agents/research-router.md`, `.claude/agents/research-editor.md`로 구현됨. 아래 A의 6개 분류명은 판단을 위한 개념적 분류이고, 실제로 라우터가 출력하는 `mode` 필드는 `research_snapshot` 파이프라인이 검증하는 `lookup`/`explain`/`analyze`/`deep_research` 4개뿐이다 — 둘의 매핑표는 `research-routing` 스킬에 있다. `deep_research`의 에이전트 상한은 18(옛 코스피 하네스 인원수)이 아니라 이 문서의 목표치인 7로 코드에 반영돼 있다(`pipeline.py`의 `MODE_MAX_AGENTS`).

#### A. 리서치 라우터

- 질문을 `lookup`, `monitor`, `document_review`, `screen`, `risk`, `deep_research`로 분류한다 (개념적 분류 — 실제 파이프라인 `mode`로의 매핑은 `research-routing` 스킬 참조).
- 필요한 데이터·계산·전문가와 토큰 예산을 구조화된 계획으로 출력한다.
- 직접 웹검색, 숫자 계산, 최종 의견 작성을 하지 않는다.

#### B. 리서치 편집자

- 검증된 Evidence Pack과 전문가 메모만 종합한다.
- `확인된 사실 / 해석 / 가설 / 반대 근거 / 미확인 / 판단 변경 조건`을 분리한다.
- 숫자를 새로 만들거나 원문에 없는 목표가·확률을 추가하지 않는다.
- 산출물을 항상 `drafts, not decisions`로 취급한다.
- 출력 스키마에 `recommendation`/`order`/`target_position` 필드 자체가 없다 (`research-editing` 스킬 참조) — 문구 필터가 아니라 구조적 제약.

#### C. 반론 검토자

- `analyze` 또는 `deep_research`에서만 호출한다.
- 가장 강한 가설의 누락 변수, 대체 설명, 출처 중복, 사후확증 편향을 검사한다.
- 단순 조회·공시 알림·정형 스크리닝에는 호출하지 않는다.

정량 검증자는 별도 AI 에이전트가 아니라 코드 검증기로 바꾼다. 숫자가 틀렸을 때 AI가
발견해 주기를 기대하지 않는다.

### 3. 필요할 때만 호출하는 전문가 풀

전문가를 시장 참여자 직함이 아니라 **판단 과제** 기준으로 구성한다.

| 전문가 | 호출 조건 | 핵심 산출물 |
|---|---|---|
| 공시·회계 분석가 | 사업보고서, 10-K/Q, 8-K, 주석 | 전기 대비 변화, 일회성, 회계 정의, 인용 근거 |
| 실적·가이던스 분석가 | 실적 발표, IR, 콘퍼런스콜 | 실적-컨센서스 차이, 가이던스 변화, 질적 원인 |
| 산업·공급망 분석가 | 피어 비교, CAPEX, 가격·물량 | 수요-공급 경로, 비교군, 산업 가설 |
| 밸류에이션 해석가 | DCF·상대가치 결과가 준비됨 | 입력 민감도와 방법별 차이 설명 |
| 거시·정책 분석가 | CPI·고용·금리·환율·정책 이벤트 | 컨센서스 대비 차이와 전달경로 |
| 시장구조·수급 분석가 | 급등락·거래량·외국인·공매도 질문 | 가격 움직임과 펀더멘털 분리 |
| 포트폴리오 리스크 해석가 | 본인 계좌 스냅샷이 있음 | 집중도·상관·VaR·스트레스 결과 설명 |
| 데이터 출처 심사자 | 출처 충돌·스크래핑·재인용 의심 | 독립 원자료 여부와 사용상 주의 |

`bull-case`, `bear-case-a`, `bear-case-b`처럼 결론을 먼저 부여한 고정 역할은 제거한다.
대신 도메인 분석가가 기본 가설을 만들고 반론 검토자가 대체 가설을 요구한다. 세 가지
시나리오가 실제로 필요한 장기 투자 테제에서만 시나리오 빌더를 임시로 추가한다.

## 다섯 개 제품 기능은 에이전트가 아니라 워크플로우다

사용자 보고서가 제안한 다섯 기능을 다섯 명의 상시 에이전트로 만들지 않는다. 각 기능은
결정적 단계와 선택적 AI 단계를 가진 독립 워크플로우로 만든다.

### 1. 공시·뉴스 모니터링

```text
DART/EDGAR/RSS 수집기 → 이전 스냅샷 diff → 규칙 기반 중요도
→ [변경이 있을 때만] 공시·회계 분석가 → 리서치 편집자 → 개인 알림
```

- 변화가 없으면 AI 호출은 0회다.
- 공시 종류, 금액 임계값, 관심종목 일치 여부는 코드로 판정한다.
- 뉴스는 원문 제공자와 재인용 기사를 `source_family`로 묶는다.

### 2. 실적 리포트 요약

```text
IR/공시/전사 수집 → 표·XBRL 결정적 추출 → 전기·컨센서스 diff
→ 실적·가이던스 분석가 → 필요 시 공시·회계 분석가 → 인용 검증 → 편집자
```

- 매출·이익·EPS·가이던스 숫자는 코드가 추출하고 계산한다.
- AI는 원인, 경영진의 조건부 표현, 사업부별 연결만 설명한다.
- 모든 핵심 문장에 원문 페이지·문단 또는 Evidence ID를 요구한다.

### 3. 산업 비교 스크리너

```text
DART/EDGAR/가격 데이터 → 피어 규칙 → 멀티플·성장률 계산 → 표 생성
→ [사용자가 이유를 물을 때만] 산업 분석가 또는 밸류에이션 해석가
```

- 기본 스크리닝은 AI 0회다.
- 피어 선정 규칙과 제외 기준을 스냅샷에 저장한다.
- 결과는 순위와 중앙값 차이로 표현하고 행동 지시를 생성하지 않는다.

### 4. 개인 포트폴리오 성과·리스크

```text
본인 계좌 읽기 전용 API → 포지션 정규화 → 수익률·VaR·집중도·스트레스 계산
→ 임계값 플래그 → [설명이 필요할 때만] 포트폴리오 리스크 해석가
```

- 주문 API, 매도 함수, 리밸런싱 실행기를 같은 프로세스에 연결하지 않는다.
- 계좌 원자료는 `self_only`, `contains_account_data=true`로 표시한다.
- AI는 비중이나 거래 시점을 결정하지 않고 계산 결과의 원인을 설명한다.

### 5. 매크로·이벤트 브리핑

```text
ECOS/FRED/공식 일정 → 캘린더 병합 → 컨센서스-실제치 차이 계산
→ 중요 이벤트만 거시 분석가 → 편집자 → 아침 브리핑
```

- 일정 수집과 별점·서프라이즈 계산은 코드가 담당한다.
- 이벤트가 시장과 산업에 전달되는 경로만 AI가 해석한다.

## 동적 수집 에이전트는 분석가와 분리한다

에이전트가 코드를 생성할 수 있더라도, 도메인 분석가가 자기 주장을 뒷받침할 데이터를
직접 찾아 수집하게 하지 않는다. 확증편향과 출처 오염을 줄이기 위해 다음 두 역할을
분리한다.

1. **수집기 작성자**: 라우터가 지정한 문서·필드만 가져오는 코드를 작성한다.
2. **데이터 계약 검증기(코드)**: 수집 범위, API 응답, 원문 해시, 필드, 날짜, 단위,
   중복과 실행 로그를 검사한다.
3. **도메인 분석가**: 검증이 끝난 Evidence Pack만 받는다.

브라우저 탐색은 API·공시 원문·RSS로 해결할 수 없을 때만 사용한다. 로그인 우회,
robots/약관 우회, CAPTCHA 우회, 대량 병렬 스크래핑을 수집기 목표로 허용하지 않는다.

## 호출 정책과 토큰 예산

| 작업 | AI 호출 기본값 | 최대 구성 |
|---|---:|---|
| 단순 조회 | 0 | 템플릿 설명 1 |
| 변화 없는 모니터링 | 0 | 0 |
| 신규 공시 요약 | 1 | 분석가 1 + 편집자 1 |
| 실적 리뷰 | 2 | 실적 분석가 + 회계 분석가 + 편집자 |
| 산업 스크리닝 | 0 | 산업/밸류에이션 해석가 1 |
| 포트폴리오 위험 리포트 | 0 | 리스크 해석가 1 |
| 복합 시장 질문 | 2~3 | 관련 전문가 2 + 반론 + 편집자 |
| 장기 투자 테제 | 4~7 | 도메인 2~3 + 시나리오 + 반론 + 편집자 |

같은 원문을 여러 에이전트에게 반복 전달하지 않는다. 원문은 한 번 추출해 Evidence ID로
등록하고, 각 에이전트에는 질문과 관련된 증거 카드만 전달한다.

## 기존 18명 구조의 마이그레이션

| 현재 역할 | 변경 |
|---|---|
| research-team-lead, scenario-team-lead, ic-chair | `리서치 편집자` 하나로 통합; 단계별 템플릿만 변경 |
| public-research-evidence-curator | `source_catalog`·중복 검출 코드로 이동; 애매한 경우만 출처 심사자 |
| quant-validator | 결정적 `validator`·`calculator`로 이동 |
| bull/bear-a/bear-b | 기본 제거; 장기 테제에서만 임시 시나리오 작업으로 생성 |
| behavioral-finance-observer | 반론 검토자의 편향 체크리스트로 통합 |
| risk-manager | 시장 리스크와 개인 포트폴리오 리스크로 분리; 후자는 읽기 전용 |
| semiconductor/macro/geopolitical/microstructure/valuation/historical | 전문가 풀로 유지하되 라우터가 선택 호출 |

`IC`라는 명칭은 개인 도구에서 실제 투자위원회나 승인으로 오해될 수 있으므로
`논리 검토`로 바꾼다. 논리 검토 상태는 매수·매도 승인이나 포지션 결정이 아니다.

## 정책 게이트 순서

```text
요청 접수
  ↓
[입력 게이트] self_only인가? 주문·타인 자금·외부 배포 요청인가?
  ↓
[수집 게이트] 허용된 출처인가? 인증·요율·스크래핑 정책이 등록됐는가?
  ↓
[데이터 게이트] redistribution, attribution, account-data 태그가 있는가?
  ↓
[분석 게이트] 원자료·산식·인용 검증을 통과했는가?
  ↓
[출력 게이트] 행동 지시·수익 보장·목표가를 새로 생성했는가?
  ↓
개인용 research_draft 저장
```

출력 게이트는 단어 몇 개를 금지하는 수준이 아니라, 산출물 구조 자체가 행동 지시 필드를
갖지 않도록 한다. 예를 들어 `recommendation`, `order`, `target_position` 대신 다음만
허용한다.

```json
{
  "observed_facts": [],
  "interpretations": [],
  "hypotheses": [],
  "counter_evidence": [],
  "unknowns": [],
  "change_conditions": []
}
```

## 권장 구현 순서

### 1단계 — 공시·실적 워크플로우

- DART와 EDGAR 고정 어댑터
- 공시 스냅샷 diff
- XBRL·표 계산기
- 공시·회계 분석가, 실적 분석가, 편집자
- Evidence ID와 인용 검증

이 단계가 데이터 권리와 구현 난도가 상대적으로 명확하고, 이후 모든 기업 리서치의
기초가 된다.

### 2단계 — 스크리너와 매크로

- ECOS·FRED 어댑터
- 피어 정의와 멀티플 계산기
- 이벤트 캘린더·서프라이즈 계산
- 산업·밸류에이션·거시 전문가의 선택 호출

### 3단계 — 읽기 전용 개인 포트폴리오

- 별도 자격증명·저장 경로
- 주문 권한이 없는 계좌 조회 클라이언트
- 위험 계산과 임계값 알림
- 계좌 데이터가 Evidence Pack 밖으로 복사되지 않는 출력 정책

### 4단계 — 기존 딥리서치 경량화

- 코스피 하네스를 라우터의 `deep_research` 선택지로 연결
- 고정 18명 호출을 질문 관련 전문가 4~7명으로 축소
- 세 시나리오는 장기 경로 의존 질문에만 생성
- 계산·출처 검증 역할을 에이전트에서 코드로 이전

## 성공 기준

- 변화 없는 모니터링 실행의 AI 호출 수가 0이다.
- 단순 조회와 스크리너의 숫자는 전부 코드로 재현된다.
- 핵심 사실의 100%가 Evidence ID와 원문 위치를 가진다.
- 동일 source family의 재인용은 독립 근거로 중복 계산되지 않는다.
- 동적 수집기 코드와 원문 파일이 모두 해시된다.
- 계좌 연결은 읽기 전용이며 주문 실행 코드가 존재하지 않는다.
- 산출물은 개인용 `research_draft`이고 외부 배포 단계가 없다.
- 복잡한 테제에서만 반론·시나리오가 호출된다.
