# Report Rendering

`research-editor`가 만든 `research_draft.json`(6개 필드만 있는 초안, 목표가·추천 필드 자체가 없음)과 `evidence/evidence_pack.json`을 하나의 정적 HTML로 조립한다. 증권사 리포트 수준의 완성도(한눈에 보기 요약, 근거 부록, 발행 고지)를 목표주가·매수의견 같은 투자 조언 요소 없이 재현하는 것이 목적이다.

## 착수 전

차트·색상·레이아웃을 다루기 전에 `dataviz` 스킬을 먼저 로드한다. 레이아웃 결정이 크면 `artifact-design`도 참조한다.

## 절대 하지 않는 것 (구조적 제약, 문구 필터 아님)

- `research_draft.json`에 없는 필드(목표가·추천·확률가중치·포지션)를 렌더러가 새로 만들어 표시하지 않는다. 스키마에 그 칸이 없으므로 렌더링할 데이터 자체가 없다는 점을 그대로 유지한다.
- "현재 판정", "결론", "매수/매도" 같은 단정형 헤더를 쓰지 않는다. 대신 "핵심 관측", "확인된 사실" 같은 사실 서술형 헤더를 쓴다 — 초안(research_draft)이 결론(decision)처럼 보이게 만들지 않는다.

## 필수 구성 (증권사 리포트 완성도 기준)

### 1. 한눈에 보기 박스 — 본문보다 먼저, 별도 시각 블록

서술형 문단에 녹이지 않고 카드/패널로 분리한다.

- **질문**: `research_draft.question`
- **확인된 사실** 상위 3~5개 (`observed_facts`, 출처 태그 포함)
- **아직 확인 못한 핵심** 상위 3~5개 (`unknowns`)
- **판단이 바뀌는 조건** (`change_conditions`의 `if`/`then` 그대로)

### 2. 사실/해석/가설/반대근거 구분 (필수)

`observed_facts`, `interpretations`, `hypotheses`, `counter_evidence` 네 범주를 색상·아이콘·헤더 스타일로 시각적으로 구분한다. 사용자가 "이건 관측된 사실"과 "이건 아직 검증 안 된 가설"을 한눈에 구분할 수 있어야 한다.

### 3. 부록: 원자료 관측값 표 (필수)

`evidence_pack.observations`를 `source_family`·증거등급별로 정리한 표를 본문 하단에 둔다 — 증권사 리포트의 재무제표 부록과 같은 역할. 본문에서 언급한 숫자를 재확인할 수 있는 단일 참조 지점이어야 한다.

### 4. 콜로폰(발행 정보) — 필수

- 이 리포트가 어떤 순서로 만들어졌는지 (라우터 → 전문가 N명 → 반론 검토 → 편집자)
- 이해관계 고지: 분석 주체가 다루는 종목/자산에 포지션이 없고, 특정 매매를 유도할 유인이 없다는 점
- 이 문서가 `research_draft`(초안)이며 `output_class` 그대로 노출 — "결정이 아니라 초안"
- 1회성 정적 스냅샷이며 자동 갱신되지 않는다는 점 (재실행하려면 새 스냅샷을 다시 빌드해야 함)

### 5. 출처 태그 시각화

모든 수치 옆에 증거등급(A~D)과 `source_family`를 표시한다. 같은 `source_family`가 여러 번 나오면 툴팁이나 범례로 "이 출처들은 같은 원자료 계열"임을 표시해, 독립 근거처럼 보이지 않게 한다.

## 쉬운말 원칙 (일반화)

기본 화면은 그 분야 전문가가 아닌 사용자를 기준으로 쓴다. 질문의 도메인에 따라 전문용어가 달라지므로 코스피 하네스처럼 고정된 치환표를 쓰지 않고, 다음 절차를 따른다.

1. 본문에서 설명 없이 쓰인 영문 약어·전문용어를 모두 찾는다
2. 각 용어를 처음 등장할 때 괄호가 아니라 문장 안에서 뜻으로 풀어 쓴다
3. 원문 추적에 필요한 정확한 용어·산식은 `<details>` 안 "전문가용 근거"에 보존한다
4. 완성 후 본문에 남은 전문용어가 하나도 없는지(또는 전부 첫 등장에서 설명됐는지) 확인한다

## 산출 및 전달

- 파일: `output/research/<run_id>/research_note.html` — 자체완결형(외부 CDN/폰트 의존 없이 인라인 CSS/JS)
- `research_draft.json`, `evidence/evidence_pack.json`으로의 상대경로 링크를 footer에 포함
- 완성 후 사용자에게 파일로 전달 — Artifact로 공개 게시할지는 항상 먼저 확인 (자기사용 전제이므로 기본은 비공개 전달)
- `lookup`/`explain`처럼 산출물이 짧을 때는 이 렌더링을 생략하고 채팅 답변으로 충분하다 — `analyze`/`deep_research`에서만 필수
