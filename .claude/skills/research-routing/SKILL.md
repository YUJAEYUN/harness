# Research Routing

`docs/personal-market-research-agent-architecture.md`의 라우터 설계를 실행 가능한 형태로 구현한다. 목표는 매 질문마다 고정된 전문가 팀 전체를 부르지 않고, 질문 성격에 맞는 최소 구성만 선택하는 것이다.

## 작업 유형 6가지 → 파이프라인 mode 4가지 매핑 (필수)

아키텍처 문서는 라우팅 판단을 위해 6가지 작업 유형을 쓰지만, 실제 구현된 `research_snapshot`(`schemas/research-request.schema.json`, `pipeline.py`의 `ALLOWED_MODES`)은 `lookup`/`explain`/`analyze`/`deep_research` 4가지 `mode`만 허용한다. 라우터가 파이프라인이 거부할 `mode`를 출력하지 않도록, 작업 유형은 아래 표로 4가지 중 하나에 반드시 매핑한다.

| 작업 유형(사용자 의도 분류) | 매핑되는 파이프라인 mode | 판단 기준 |
|---|---|---|
| 단순 조회 | `lookup` | 이미 수집된 관측값을 그대로 보여주면 됨, 해석 불필요 |
| 변화 없는 모니터링 | `lookup` (AI 호출 0) | 이전 스냅샷과 `compare_snapshots` 결과 `added`/`removed`/`changed`가 모두 비어있음 |
| 변화 있는 모니터링(신규 공시 등) | `explain` | 변화가 감지됐고, 그 변화 하나를 설명하는 수준 |
| 문서 해석(실적·공시 본문) | `explain` 또는 `analyze` | 단일 문서 요약이면 `explain`, 여러 문서·전기 비교가 필요하면 `analyze` |
| 스크리닝(피어 비교) | `lookup` 또는 `analyze` | 표만 보여주면 `lookup`, "왜 이런 결과인지" 설명 요청이 있으면 `analyze` |
| 포트폴리오 리스크 | `explain` 또는 `analyze` | 단일 지표 설명이면 `explain`, 집중도·상관관계까지 엮으면 `analyze` |
| 복합 시장 질문 / 장기 투자 테제 | `deep_research` | 단일 문서·단일 지표로 안 끝나고, 여러 전문가·반론검토가 필요 |

## 에이전트 예산 표 (파이프라인과 반드시 동기화 유지)

| mode | 최대 에이전트 수 | 근거 |
|---|---:|---|
| `lookup` | 0 | 코드가 값을 그대로 보여줌, AI 해석 불필요 |
| `explain` | 1 | 단일 전문가가 이미 검증된 사실을 설명 |
| `analyze` | 3 | 도메인 전문가 최대 2 + 반론 검토자 1 |
| `deep_research` | 7 | 도메인 전문가 2~3 + 시나리오/반론 + 편집자 — 코스피 하네스의 고정 18명 방식을 쓰지 않는다 |

이 표의 숫자가 `research_snapshot/pipeline.py`의 `MODE_MAX_AGENTS`와 달라지면(코드가 먼저 바뀌었거나 이 스킬이 먼저 바뀌었거나) 반드시 둘 다 같은 리뷰에서 맞춘다 — 어긋난 채로 두면 라우터가 짠 계획이 파이프라인에서 거부되거나, 반대로 파이프라인은 허용하는데 라우터가 불필요하게 예산을 적게 잡는 문제가 생긴다.

## 라우팅 절차

1. 질문에서 "이미 수집된 데이터로 답이 되는가"부터 확인한다 — 그렇다면 `lookup`, AI 호출 0
2. 안 된다면 "새로 필요한 데이터가 있는가"를 확인하고, 있다면 `required_sources`에 `existing`(이미 있는 소스 재사용) 또는 `needs_new_adapter`(새 수집기 필요)로 표시한다. 라우터는 어댑터를 직접 짜지 않는다 — 필요성만 표시
3. 필요한 계산(변화율·멀티플·컨센서스 차이 등)을 나열한다 — 라우터가 직접 계산하지 않는다
4. 필요한 전문가를 **판단 과제 기준**으로 고른다 (시장 참여자 직함이 아님): 공시·회계 분석가 / 실적·가이던스 분석가 / 산업·공급망 분석가 / 밸류에이션 해석가 / 거시·정책 분석가 / 시장구조·수급 분석가 / 포트폴리오 리스크 해석가 / 데이터 출처 심사자
5. `analyze` 또는 `deep_research`일 때만 반론 검토자를 계획에 포함한다
6. 위 매핑표로 최종 `mode`를 정하고, 예산 표의 상한을 넘지 않는 `max_agents`를 부여한다

## 하지 않는 것

- 웹검색이나 실제 데이터 수집을 직접 하지 않는다 (그건 어댑터/수집기의 역할)
- 숫자를 계산하지 않는다 (그건 `calculator`/전문가의 역할, 아직 미구현이면 "계산 불가"로 명시)
- 최종 결론이나 의견을 작성하지 않는다 (그건 `research-editor`의 역할)
