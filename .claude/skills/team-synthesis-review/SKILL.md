# Team Synthesis Review — 팀장 검수/종합 방법론

리서치팀장과 시나리오팀장이 공통으로 쓰는 검수·종합·에스컬레이션 절차. `data-sourcing-protocol` 위에서 동작한다.

## 검수 절차

1. **출처 태그**: 모든 수치에 RAW/OFFICIAL/REPORT/WEB/DERIVED/ASSUMPTION 태그와 필요한 원문 정보가 있는가.
2. **결론 배제**: 리서치 실무자 8명과 팀장, quant-validator, behavioral-finance-observer가 투자 결론 없이 사실·1차 해석에 머물렀는가.
3. **사실관계**: 다른 산출물과 상충하는 값이 삭제·평균되지 않고 정의와 함께 병기됐는가.
4. **준원자료 독립성**: 보고서 발행사 수와 원 데이터 source family 수가 구분됐는가.
5. **관측값/가정 분리**: 목표가·스트레스 가정이 실제 역사 관측값 또는 실시간 판별 트리거로 표현되지 않았는가.
6. **의사결정 연결성**: 핵심 수치가 현재 판정과 “무엇이 확인되면 판단이 바뀌는가”에 연결됐는가.

기준 미달이면 어느 claim과 필드가 문제인지 구체적으로 전달해 재작업을 지시한다.

## 2단계 에스컬레이션 사다리

팀원으로부터 NEEDS_CLARIFICATION을 받으면 같은 팀의 산출물과 evidence registry로 먼저 교차검증한다.

1. 조정 가능하면 팀 안에서 해결하고 `_workspace/kospi-bottom/{phase}_{team}_escalation_log.md`에 기록한다.
2. 조정이 안 되거나 시나리오 방향을 바꾸는 핵심 항목이면 PM에게 올린다.

## 종합 보고서 작성 원칙

- 원 산출물의 출처 태그·증거등급·source family를 유지한다.
- 상충 정보는 삭제하지 않고 정의 차이와 함께 병기한다.
- 하나의 결론으로 강제 수렴시키지 않는다.
- 리서치 종합본 첫 부분에 현재 판정/확인된 근거/미확인 핵심/판단 변경 조건을 표로 제시한다.
- 역사적 관측 범위와 시나리오 민감도 가정을 별도 표로 분리한다.

## PM 에스컬레이션 형식

```text
## [항목명]
- 보고 팀원:
- 상충/불확실 내용:
- 후보값과 증거등급:
- source family:
- 시나리오 영향도:
```
